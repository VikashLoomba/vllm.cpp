## Build recipe

```sh
cmake -B build -G Ninja \
  -DVLLM_CPP_HIP=ON \
  -DVLLM_CPP_HIP_ARCHITECTURES=gfx1100 \
  -DCMAKE_BUILD_TYPE=Release
ninja -C build -j 4
```

Both arms built clean from scratch with `--offload-arch=gfx1100`. The `-j 4`
limit avoids OOM on the 64 GiB host when the ROCm compiler spikes.

## Run commands

```sh
vllm-bench --model ~/models/vllm.cpp/Qwen3.5-4B-Q4_K_M.gguf \
  --input-len L --output-len 1 --num-prompts 5 \
  --concurrency 1 --seed 42 --temperature 0
```

PP lengths: 28, 64, 128, 228, 911, 1821. Five reps per length, interleaved
A B per rep (baseline, then hw-dp4a, alternating).

## Environment and contention

- No other GPU workloads running during the A/B (single-user host).
- GPU idle 60s before the post-cooldown focused run.
- No `flock` or `rc` lease: this is a personal workstation, not a fleet
  device. The file mutex `${GPU_LOCK:-$HOME/gpu.lock}` was held.
- Thermal: baseline clean build showed extreme variance at PP>=128 (some
  reps 2-4x slower than the stable floor), likely GPU thermal throttling
  during the 17-minute run. The hw-dp4a arm was more consistent. The
  post-cooldown focused run (60s idle) reduced this variance.

## Correctness verification

1. **test_ops_quant_dot**: 28 test cases, 210138 assertions, all pass.
2. **test_backend_cross_device** ("non-grouped keep-quant GEMM"): 4 NMSE
   assertions pass (Q8_0/Q4_K/Q5_K/Q6_K, all ≤ kNmseTol).
3. **SIGSEGV**: pre-existing on clean builds. Proven by clean-building the
   baseline (pp-opt) branch — identical SIGSEGV during ROCm runtime teardown
   after all assertions pass. The stale incremental pp-opt build did not
   crash, masking the issue.
4. **Token-exact**: both binaries produce identical output tokens at
   seed=42, temperature=0, verified via vllm-bench.
