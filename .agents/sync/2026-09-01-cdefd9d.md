## 9. Gateability of the target

**`gateable = no`. The structural blocker is gone; the measurement is still
owed.**

AGENTS.md: an oracle is gateable only once it demonstrably builds and runs the
model, and constructing a config proves nothing. Nobody has built
`cdefd9d499`, or `adebc41b7e` before it. The evidence remains that the tree
contains no reference to either SHA outside this report and its predecessor.

What the unshallow changed, and what it did not:

- **Changed.** A shallow clone cannot produce the `vllm_runtime_version` string
  the `parity-pin` block requires. `setuptools_scm` cannot count commits since
  the last tag and falls back to a default, which is exactly the open
  discrepancy in [#1185](https://github.com/mudler/vllm.cpp/issues/1185): one
  measured build inside an `rc` lease reported `0.1.dev1+g555967922` against the
  recorded `0.23.1rc1.dev1511+g555967922`. With the full history the tag count is
  available, so a build from this checkout can now report the real string. The
  `+g<sha>` constraint `assert_oracle_commit` enforces is satisfiable for the
  target.
- **Not changed.** No build has run. No `vllm.__version__` has been measured at
  the target, no wheel exists, no venv, and no run on any fleet device. A
  reachable history is a precondition for the version string, not a substitute
  for the build.

revisions:
